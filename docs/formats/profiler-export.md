# Profiler Export V1

The CSV and JSON export of recorded profiler frames (plan 0002 WP6.3, contract §2 rule 11, §13),
implemented in `grimoire_debug` (`crates/grimoire_debug/src/export.rs`, `ProfileLog::write_csv` and
`ProfileLog::write_json`). Like `bench-result.md`, this page is **hand-written**, not generated by
`grimoire_schemagen`: it describes a text export of the debug protocol's `Stats` payload, not a
wire format.

Schema name **`grimoire.profiler.export`**, format version **1** (`PROFILE_EXPORT_SCHEMA`,
`PROFILE_EXPORT_SCHEMA_VERSION`).

## Source of the data

A `ProfileLog` holds one `Stats` value per frame, built by `FrameProfile::to_stats` exactly like
the payload of a debug-protocol `Stats` message (contract §13 catalogue, id `0x0010`). Both
exports therefore carry the same values, truncated the same way: at most 64 scopes and 64
counters per frame, in order of first recording, every name cut at a UTF-8 character boundary to
at most 64 bytes. Durations are nanoseconds, `u64::MAX` when they overflowed.

## JSON

One document, UTF-8 without BOM, keys in exactly the order below, a single trailing newline.

```json
{"schema":"grimoire.profiler.export","schema_version":1,"frames":[
  {"frame":0,"sim_tick":1,"ticks_this_frame":1,"alpha":0.5,"frame_time_ns":16666667,"fps":60,
   "dropped_time_ns":0,"content_swaps":0,"content_manifest":"0000000000abcdef",
   "scopes":[{"scope":1,"name":"sim","total_ns":1250000,"calls":1,"budget_ns":4000000,"estimate":false}],
   "counters":[{"name":"bullets_drawn","value":10000}]}
]}
```

(Wrapped here for reading; the writer emits no whitespace between tokens.)

### Envelope

| Field | Type | Value |
|---|---|---|
| `schema` | string | `"grimoire.profiler.export"` |
| `schema_version` | integer | `1` |
| `frames` | array of `Frame` | in push order |

### `Frame`

| Field | Type | Meaning |
|---|---|---|
| `frame` | integer | frame index, starting at 0 |
| `sim_tick` | integer | simulation tick count after the frame's ticks |
| `ticks_this_frame` | integer | ticks simulated in the frame |
| `alpha` | number | interpolation factor of the frame (`f32`) |
| `frame_time_ns` | integer | real time since the previous frame |
| `fps` | number | frames per second (`f32`) |
| `dropped_time_ns` | integer | total real time the fixed timestep discarded so far |
| `content_swaps` | integer | Sigil unit swaps applied so far (contract §11.8) |
| `content_manifest` | string | content-manifest hash, exactly 16 lowercase hex digits |
| `scopes` | array of `Scope` | at most 64 |
| `counters` | array of `Counter` | at most 64 |

### `Scope`

| Field | Type | Meaning |
|---|---|---|
| `scope` | integer | `ScopeId` (the facade: loop scopes 0 to 4, subsystems in order of first appearance) |
| `name` | string | scope name, at most 64 bytes |
| `total_ns` | integer | sum of the scope's recordings in the frame |
| `calls` | integer | number of recordings in the frame |
| `budget_ns` | integer | budget of the scope, `0` for none |
| `estimate` | boolean | `true` if at least one recording was a fallback without a real measurement (for example GPU time without timestamp queries) |

### `Counter`

| Field | Type | Meaning |
|---|---|---|
| `name` | string | counter name, at most 64 bytes |
| `value` | integer | counter value for the frame |

### Rules (contract §2 rule 11)

- Every integer is at most 2^53 − 1. A larger value (for example a saturated `u64::MAX` duration)
  fails the export with `ExportError::IntegerTooLarge`; nothing is written.
- `alpha` and `fps` are finite. NaN or infinity fails with `ExportError::NonFinite`; nothing is
  written. Numbers are printed without an exponent and with the shortest digits that read back as
  the same `f32`.
- `content_manifest` is a hash and therefore a hex string, never a number.
- Strings escape `"`, `\` and control characters (`\n`, `\r`, `\t`, otherwise `\u00XX`).

## CSV

UTF-8, `\n` line endings, RFC 4180 quoting (a field containing `,`, `"` or a line break is quoted,
quotes are doubled). The header row is fixed:

```text
frame,sim_tick,ticks_this_frame,alpha,frame_time_ns,fps,dropped_time_ns,content_swaps,content_manifest,kind,scope,name,total_ns,calls,budget_ns,estimate,value
```

Each frame contributes one row per scope, then one row per counter, all starting with the frame's
nine columns (`content_manifest` as 16 lowercase hex digits):

| `kind` | Filled columns | Empty columns |
|---|---|---|
| `scope` | `scope`, `name`, `total_ns`, `calls`, `budget_ns`, `estimate` (`true`/`false`) | `value` |
| `counter` | `name`, `value` | `scope`, `total_ns`, `calls`, `budget_ns`, `estimate` |
| `frame` | — (only for a frame with neither scopes nor counters) | all seven |

CSV has no number limits: saturated durations and non-finite floats are written as they are
(`18446744073709551615`, `NaN`, `inf`), so only I/O can fail.

## Scope names of the facade

The main loop of `grimoire::App` (contract §9.7, `grimoire::adapters::debug`) records:

| Scope | Content | Default budget |
|---|---|---|
| `frame` | the loop's work from the frame's clock reading to the end of `on_frame` | 16.67 ms |
| `sim` | sum of every `Simulation::step` of the frame | 4 ms |
| `extract` | every plugin's `extract` and `extract_stage` | 0.5 ms |
| `render` | the `render_stage` call, including submission and presentation | 3 ms |
| `gpu` | summed pass time from timestamp queries, lagging one to three frames; without timestamp queries the `render` time, marked `estimate` | 8 ms |
| `<prefix>` | systems named `<prefix>.<name>`, e.g. `sigil` (1 ms), `collide` (1.5 ms) | see `DEFAULT_BUDGETS` |
| `app` | systems without a prefix, or whose prefix is one of the loop scopes | none |

Counters: `bullets_drawn`, `bullets_rejected_palette_space`, `bullets_rejected_invalid`.

## Versioning

A new column, key or changed meaning increases the format version. Readers compare `schema` and
`schema_version` (JSON) or the header row (CSV) before reading.
