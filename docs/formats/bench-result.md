# Bench Result V1

The bench-result JSON Lines format (engine contract §15.1), implemented in `grimoire_bench`
(`crates/grimoire_bench/src/schema.rs`). Unlike `pack.md` and `debug-protocol.md` in this
directory, this page is **hand-written**, not generated by `grimoire_schemagen`: contract §15.1
is a JSON schema for a tool crate's own bench output, not a binary wire format the schema
generator (project ADR-0011) owns.

Schema name **`grimoire.bench.result`**, format version **1**.

## Purpose

One `BenchResult` is one line of a JSON Lines file: the output of a single bench run, and — once
appended to the trend branch (P-12, `bench-trends`) — one row of the measurement history. The
line form is identical in both roles.

## Envelope

Every line starts with a fixed envelope, checked (not stored) by the reader:

| Field | Type | Value |
|---|---|---|
| `schema` | string | `"grimoire.bench.result"` |
| `schema_version` | u32 | `1` |

An unknown `schema` or a higher `schema_version` than this reader understands is a
`SchemaError`, never a panic; so is any missing or unknown field.

## Fields

| Field | Type | Constraint |
|---|---|---|
| `scenario` | string | `[a-z0-9_]{1,64}`, stable across runs (e.g. `ecs_query_10k`, `sim_step_600`) |
| `metric` | string | `[a-z0-9_]{1,32}`; v1 known values `wall_time`, `instructions`; more per engine ADR-0010 |
| `unit` | string | one of `ns`, `ir`, `count`, `bytes` |
| `median` | f64 | finite; must equal the median [`grimoire_bench::schema::median`] computes from `samples` |
| `samples` | array of f64 | at least one entry, at most 100,000; every value finite and `>= 0`, in measurement order |
| `commit` | `CommitRef` | see below |
| `runner` | `RunnerInfo` | see below |
| `executor` | `ExecutorInfo` | see below |
| `params` | object | bench parameters (ticks, rounds, entity counts, …); at most 64 entries; extensible |
| `value_origin` | string | one of `runner`, `reference`, `estimate` |
| `injected_regression_percent` | u32 | `0` except in the calibration self-test |
| `run` | `RunKey` or `null` | CI run identity, when known |

### `CommitRef`

| Field | Type | Constraint |
|---|---|---|
| `sha` | string | exactly 40 lowercase hex characters |
| `dirty` | bool | `true` if the working tree had uncommitted changes; a dirty commit is never judged by a comparator |

### `RunnerInfo`

| Field | Type | Constraint |
|---|---|---|
| `os` | string | e.g. `"linux"` |
| `arch` | string | e.g. `"x86_64"` |
| `image` | string or `null` | CI runner image, when known (e.g. `"ubuntu-24.04"`) |
| `cpu_model` | string or `null` | CPU model string, when known |
| `logical_cpus` | u32 | logical CPU count |
| `fingerprint` | object | extensible tool-version fingerprint, e.g. `{"valgrind": "3.22.0"}`; at most 64 entries |

### `ExecutorInfo`

| Field | Type | Constraint |
|---|---|---|
| `kind` | string | `"sequential"` or `"thread_pool"` |
| `threads` | u32 | `>= 1`; must be exactly `1` when `kind == "sequential"` |

A result with `executor.threads > 1` may only report `metric == "wall_time"` — the Callgrind gate
(engine ADR-0010) is single-threaded only (Valgrind serialises threads).

### `RunKey`

| Field | Type | Constraint |
|---|---|---|
| `id` | string | opaque run id (e.g. a GitHub Actions run id) |
| `attempt` | u32 | attempt number within that run |

## Example

One line, wrapped here for readability:

```json
{"schema":"grimoire.bench.result","schema_version":1,"scenario":"ecs_query_10k",
 "metric":"instructions","unit":"ir","median":48211377,"samples":[48211377],
 "commit":{"sha":"f5c9bf5000000000000000000000000000000000","dirty":false},
 "runner":{"os":"linux","arch":"x86_64","image":"ubuntu-24.04","cpu_model":null,
           "logical_cpus":4,"fingerprint":{"valgrind":"3.22.0"}},
 "executor":{"kind":"sequential","threads":1},
 "params":{"entities":10000,"rounds":100},
 "value_origin":"runner","injected_regression_percent":0,"run":null}
```

## Comparability

Two results are comparable only if `scenario`, `metric`, `unit`, `executor` and `params` are all
equal, and neither `commit.dirty` is `true` (`grimoire_bench::schema::BenchResult::comparable_to`).
Otherwise there is measurement without judgement; the regression gate's exit codes are defined by
engine ADR-0010 §4.3, implemented in `grimoire_bench::gate`.

## Size limits

Checked by the reader before parsing, and by the writer before returning a line:

| Constant | Value |
|---|---|
| `MAX_BENCH_LINE_BYTES` | 64 KiB |
| `MAX_SAMPLES` | 100,000 |
| `MAX_PARAMS` | 64 |
| `MAX_FINGERPRINT_ENTRIES` | 64 |
| `MAX_TEXT_BYTES` | 1024 |

## Scope note (WP6.2)

Engine contract §15 also defines a `GoldenMaster` format (§15.2) sharing this crate. WP6.2 (the
benchmark gate) does not implement it — no golden-master bench exists yet — so this page and
`grimoire_bench::schema` cover only §15.1. A future work package that needs `GoldenMaster` should
add it (and its own `docs/formats/` page) rather than assume it already exists here.
